# Как устроены исходники кампании

В корне авторской папки и готового ZIP-архива `.districtdeck` лежит `campaign.yaml`. Имя архива произвольно. Постоянный `id` в манифесте обозначает кампанию, `name` показывается игроку, а `version` — строка свободного формата. Версию, похожую на число, пишут в кавычках. Образец для первой версии движка — [манифест «Последнего поезда»](../Fixtures/Campaigns/LastTrain/campaign.yaml).

## Где искать данные

| Путь от корня кампании | Что задаёт автор |
| --- | --- |
| `board/map.yaml` | Граф движения, названия клеток и территорий, принадлежность клеток территориям. |
| `board/scene.yaml` | Фон, области выбора клеток, места для фишек, повороты дорог и объекты карты. |
| `characters/<id>.yaml` | Имя персонажа и его собственные правила, если нужны. Состав партии и начальную раскладку задаёт манифест. |
| `items/<id>.yaml` | Предмет или игровой ресурс. Обязательное поле `owner` принимает `character` или `party`. Видимость в инвентаре по умолчанию включена. |
| `events/…/<id>.yaml` | Текст встречи, подсказки для карты и скрипт ответов с их эффектами. |
| `quests/…/<id>.yaml` | Видимое задание, условие выполнения и эффекты выдачи и завершения. |
| `story/…/<id>.yaml` | Текст сюжетной точки, её эффекты и, для продолжающегося сюжета, шкала с переходами. |
| `resources/` | Файлы оформления по назначению. Например, обе картинки поля лежат в `resources/board/`. |

В каталогах персонажей, предметов, событий, квестов и сюжетных точек действует правило «одна сущность — один YAML». Файлы находятся и в подпапках. Имя файла без расширения совпадает с `id`, который уникален среди сущностей этого вида во всей кампании. Отдельный перечень файлов в манифесте не нужен. Встречи одного квеста удобно держать вместе, как в [events/collect-parcel/](../Fixtures/Campaigns/LastTrain/events/collect-parcel/). Для встречи, которую добавили на вокзал после выполнения квеста, подходит [events/station/](../Fixtures/Campaigns/LastTrain/events/station/).

## Как читать ссылки

| Запись | Что она находит |
| --- | --- |
| `initialStoryPoint: send-parcel` | Сюжетную точку по ID. Тип ссылки задаёт поле YAML. |
| `(placeEvent .post-office .post-office position: top)` | Первое имя обозначает событие, второе — территорию. Типы аргументов задаёт команда. |
| `image: "@board/train.png"` | Файл `resources/board/train.png`, из какого бы YAML на него ни ссылались. Строку с начальным `@` в YAML заключают в кавычки. |

Файлу с художественным текстом можно сменить подпапку внутри `events/`, сохранив его ID и все ссылки на встречу. При переносе изображения меняется путь после `@`. Игровая монета — описание в [items/coin.yaml](../Fixtures/Campaigns/LastTrain/items/coin.yaml). Поезд — объект сцены с ID `train`, а картинка этого объекта — файл оформления. Скрипт показывает поезд командой `(addObject .train)`.

## Как связать раскладку, встречу и сюжет

1. **Старт.** Манифест задаёт состав в `characters`. При отсутствии `allowed` доступны все персонажи из каталога. Один обязательный ID можно записать строкой в `required`, несколько — списком. Обязательные участники входят в `maxCount`. Выбранные персонажи начинают в `initialPoint`, затем один раз выполняется `onStart` и открывается `initialStoryPoint`. В «Последнем поезде» именно здесь Иван получает пять личных монет.
2. **Выдача квеста.** У квеста `goal`, необязательный `text`, `onStart`, `completeWhen` и `onComplete` лежат в корне YAML. Квест сам указывает, в какую территорию и на какое место положить каждую карту. Обе возможности забрать посылку получают `forQuest: (currentQuest)`. Когда одна срабатывает, оставшаяся копия убирается. Проводника квест добавляет без `forQuest:`, и тот остаётся на вокзале после завершения задания. [Квест «Забрать посылку»](../Fixtures/Campaigns/LastTrain/quests/collect-parcel.yaml)
3. **Текст и решение.** Для повествования и прямой речи удобно использовать `text: |-`. Пустая строка отделяет реплику с тире от авторского абзаца. В `script: |` лежит одно выражение языка. У курьера `hasItem` с `atLeast: 5` определяет доступность оплаты, а `removeItem` с `count: 5` списывает монеты только после выбора. На почте подтверждение единственного ответа выдаёт посылку. [Курьер](../Fixtures/Campaigns/LastTrain/events/collect-parcel/courier.yaml) · [Почта](../Fixtures/Campaigns/LastTrain/events/collect-parcel/post-office.yaml) · [Язык скриптов](ScriptLanguage.md)
4. **Отметка и переход.** В конце раунда после встреч выполняется `onRoundEnd`. Затем в порядке записи разыгрываются достигнутые `track.milestones`, после них проверяются `track.transitions` до первой подходящей строки. У отметки `at` задаёт порог, `script` — эффект. У перехода `at` задаёт порог, `when` — дополнительное условие, `to` — ID назначения, `description` — короткое пояснение на шкале. На двух очках отчаяния поезд появляется к началу третьего раунда. При доставке в пятом раунде подходят оба перехода, и порядок строк определяет развязку. [Точка «Отправить посылку»](../Fixtures/Campaigns/LastTrain/story/send-parcel.yaml)
5. **Развязка.** В конечной точке достаточно текста, поле `track` можно опустить. При входе всё ещё выполняется `onEnter`. В обеих развязках этот скрипт убирает поезд, а движок сохраняет достигнутую точку как результат партии. [Посылка отправлена](../Fixtures/Campaigns/LastTrain/story/parcel-sent.yaml) · [Поезд ушёл](../Fixtures/Campaigns/LastTrain/story/train-left.yaml)

## Как совместить граф с рисунком

В `board/map.yaml` пара ID в `edges` задаёт одну двустороннюю дорогу стоимостью в один шаг. У клетки может быть одна территория. Обе клетки вокзала ссылаются на `station`, поэтому у них одна колода встреч. [Граф карты](../Fixtures/Campaigns/LastTrain/board/map.yaml)

В `board/scene.yaml` для клетки с тем же ID задают контур выбора `polygon` и точку остановки `pawn`. Координаты заданы в пикселях холста `size` от левого верхнего угла. Для объекта `position` задаёт центр изображения. Запись в `objects` описывает доступный объект, его присутствие на карте меняет скрипт. Поэтому на фоне нарисованы пустые рельсы, а поезд вынесен в отдельный PNG с прозрачностью. [Сцена с поездом](../Fixtures/Campaigns/LastTrain/board/scene.yaml)

Для дороги с поворотами в `edgePaths` указывают пару клеток `edge` и промежуточные точки `via`. К концам пути сцена подставляет `pawn` обеих клеток. В обратную сторону фишка проходит повороты в обратном порядке. Если запись опущена, фишка идёт по прямой. Дальность движения в обоих случаях считается по рёбрам графа.

## Что проверить перед игрой

По договорённости `CampaignTool` при сборке и приложение при открытии архива используют общий валидатор. Он проверяет поля YAML, имена файлов и ID, типы ссылок и команд, соответствие клеток и дорог сцены графу. Каждая ссылка `@` должна разрешаться в существующий файл внутри `resources/`. Диагностика указывает причину, путь от корня кампании, строку и столбец с единицы. [Требования к сборщику](Tasks/last-train-first-play/2026-11-14-build-load-campaign-archive.md)

Для проверки самого приключения используются три эталонных маршрута из одной раскладки. Они проверяют оплату и отказ у курьера, получение посылки на почте, одновременное совпадение переходов и опоздание. Результаты по раундам и ожидаемый инвентарь приведены в [сценарии «Последнего поезда»](Campaigns/LastTrain.md#три-прохождения-из-одной-раскладки).
