# Спроектировать язык скриптов встреч

Спроектировать собственный язык встреч на основе типизированных выражений в Lisp-подобной нотации из референса. При чтении скрипта ядро строит Swift-структуры и проверяет аргументы каждой команды. Ранее рассмотренные способы записи сохранены ниже для сравнения. Границы первой версии согласуем с автором проекта. Первый потребитель — [исходники «Последнего поезда»](last-train-first-play/2026-11-14-write-last-train-campaign.md).

**Итог обсуждения.** Все шесть вопросов по первой версии языка разобраны. Согласованный формат ошибок для `CampaignTool` и приложения приведён в [справочнике языка](../ScriptLanguage.md#диагностика-ошибок-скрипта).

Карточку можно закрыть, когда автор выбрал формат и по примерам понятны порядок команд, доступность ответов, ветвление, граница с игровым движком, ошибки при сборке и повторный запуск прерванного скрипта. Результат — описание с примерами, по которому можно написать три встречи «Последнего поезда».

## Документ для ревью

[Язык скриптов DistrictDeck](../ScriptLanguage.md) описывает согласованные правила записи, проверки и исполнения. В карточке сохранены рабочие предложения, сравнение языков и примеры для проверки решений.

Согласованные [правила результатов выражений](../ScriptLanguage.md#результаты-выражений) расширяют последовательность действий из прототипа. У `do` результат определяется последним шагом. Одинаковый тип веток `if` сохраняет поведение референса. [Исходный do](../../Reference/Utils/Script/Sources/Script/Expression/Expressions/Do.swift) · [Исходный if](../../Reference/Utils/Script/Sources/Script/Expression/Expressions/If.swift)

## Словарь «Последнего поезда» (вопрос 3 из 6, предложение)

Для предметов и ресурсов согласованы действия `addItem`, `removeItem` и формы чтения `hasItem` с необязательным минимумом `atLeast:` и `itemCount`. Для `placeEvent` согласована явная привязка через `forQuest:`. Остальные имена и сигнатуры ниже предложены для обсуждения на примере трёх встреч, одного квеста и трёх сюжетных точек кампании. Названия действий движка и типы аргументов одинаковы для всех мест запуска. [Сценарий и эталонные маршруты](../Campaigns/LastTrain.md)

| Что нужно автору | Предлагаемая запись | Результат и контекст |
| --- | --- | --- |
| Проверить и изменить инвентарь участника встречи | `(hasItem .token)`, `(addItem .parcel)`, `(removeItem .token)` | Проверка возвращает `Bool` и поддерживает `hint:`. Два действия возвращают `Void`. В этих примерах жетон и посылка принадлежат участнику встречи. Для общего ресурса те же операции обращаются к инвентарю партии. |
| Найти посылку среди личных вещей персонажей партии | `(hasItem .parcel in: all)` | Для личного предмета `itemCount` с `in: all` возвращает сумму по личным инвентарям участников партии. `hasItem` сравнивает эту сумму с `atLeast:`. По умолчанию достаточно одной посылки. |
| Показать варианты и реплику | `chooseOne`, `case`, `caseIf`, `say` | На почте и вокзале один авторский вариант, у курьера два. Движок ждёт подтверждения и возвращает результат выбранной ветки. [Выбор игрока](../ScriptLanguage.md#выбор-игрока) |
| Выдать квест | `(startQuest .collect-parcel)`, `(startQuest .collect-parcel repeatable: true)` | `Void`. По умолчанию `repeatable: false` разрешает только первую выдачу. После выполнения или отмены повторная выдача возможна с `repeatable: true`. Пока квест активен, оба варианта пропускают выдачу и её эффекты. |
| Отменить квест | `(cancelQuest .collect-parcel)` | `Void`. Отменяет только активный квест. При любом другом состоянии скрипт идёт дальше. [Правило отмены](../ScriptLanguage.md#отмена-квеста) |
| Положить событие наверх колоды территории | `(placeEvent .courier .square position: top forQuest: (currentQuest))` | `Void`. Первые два аргумента — ID события и территории. В «Последнем поезде» позиция `top` кладёт новую копию наверх. Необязательный владелец связывает экземпляр карты с активным квестом для последующей очистки. |
| Начислить надежду или проверить порог отчаяния | `(addItem .hope)`, `(hasItem .despair atLeast: 5)` | Обычная выдача ресурса партии и проверка его количества. Возможные сокращения используют ту же позицию инвентаря. |
| Соединить условия или получить обратное значение | `and`, `or`, `not` | Аргументы и результат имеют тип `Bool`. [Правила вычисления](../ScriptLanguage.md#условия-ответы-и-эффекты) |

**Встречи.** Во встречу движок передаёт персонажа, вытянутую карту и территорию. Для этих трёх скриптов достаточно обращаться к инвентарю участника, а у проводника — ещё к надежде в общем инвентаре. У курьера проверка жетона только управляет доступностью обмена. Тело ответа — `(do (removeItem .token) (addItem .parcel))`, при отказе — `(say "Тогда заберёте посылку на почте.")`. На почте подтверждение «Забрать посылку» вызывает `(addItem .parcel)`. У любого входа на вокзал подтверждение «Передать посылку» запускает один блок:

```lisp
(do
  (removeItem .parcel)
  (addItem .conductor-note)
  (addItem .hope))
```

**Квест «Забрать посылку».** При выдаче известен текущий квест. Обе карты привязываются к нему явно, а целевые территории автор указывает по ID:

```lisp
(do
  (placeEvent .courier .square position: top forQuest: (currentQuest))
  (placeEvent .post-office .post-office position: top forQuest: (currentQuest)))
```

В примере событие почты и территория почты имеют одинаковый короткий ID в разных каталогах. Сигнатура различает их по позиции. При получении посылки условие `(hasItem .parcel in: all)` выполняется. Движок завершает квест и убирает его оставшиеся карты из колод. Правило завершения вызывает `(placeEvent .conductor .station position: top)`. У этой карты нет привязки к завершённому квесту. Вытянутая встреча после розыгрыша попадает в сброс, а подсветка пересчитывается по картам в колодах.

**Точка «Отправить посылку».** При открытии — `(startQuest .collect-parcel)`. В конце раунда после встреч — `(addItem .despair)`. Точка проверяет количества надежды и отчаяния в общем инвентаре. После начисления движок проверяет строки переходов в порядке записи:

| Условие | ID следующей точки в YAML |
| --- | --- |
| `(and (hasItem .conductor-note in: all) (hasItem .hope))` | `parcel-sent` |
| `(hasItem .despair atLeast: 5)` | `train-left` |

Движок открывает первую подходящую точку. Если обе строки ложны, начинается следующий раунд. После розыгрыша любой из двух конечных точек движок завершает партию с этой развязкой. На маршруте курьера первая строка срабатывает в раунде 3. Через почту в раунде 5 подходят обе строки и побеждает первая по порядку. При задержке в раунде 5 есть посылка, но нет записки, и срабатывает вторая строка.

## Исполнение и диагностика: варианты к обсуждению

- **Позиция ошибки.** При проверке реализации сверить путь, строку и столбец с исходным YAML. Для многострочного блока важны отступы, а для свёрнутого текста нужно учесть преобразование переносов. [Формат сообщения](../ScriptLanguage.md#диагностика-ошибок-скрипта)
- **Ожидание игрока.** В референсе `chooseOne` вызывает `await currentPlayer.ask(...)` и исполняет выбранную ветку после ответа. Для обсуждения реализации можно взять тот же подход. Пока партия открыта, UI или тест передаёт ответ, а ожидающий `if` получает результат через обычный вызов. При загрузке движок запускает прерванную встречу с начала.

## Предложение по контексту выполнения

Все скрипты обращаются к состоянию одного прохождения через команды движка. Им доступны проверки ресурсов и инвентарей, положения персонажей, активных квестов и счётчиков текущей цели. Источник запуска известен движку и позволяет объяснить эффект в журнале.

| Место запуска | Что известно при запуске | Кто за что отвечает |
| --- | --- | --- |
| Встреча | Конкретная вытянутая карта, территория её колоды и персонаж, разыгрывающий встречу. | Скрипт может указать участника встречи как получателя посылки или добавить копию текущей карты в колоду. По завершении розыгрыша движок сам отправляет исходную карту в сброс и продвигает очередь. |
| Квест | Конкретный квест и повод запустить его правило, например выдача, проверка выполнения, выполнение или отмена. | Квест проверяет условие, а движок завершает его при успехе. События, добавленные для активного квеста, связаны с ним до очистки. В «Последнем поезде» скрипт выполнения добавляет проводника на вокзал для основной цели. Ему нужен ID территории, а личный получатель для этой команды не нужен. |
| Сюжетная точка | Активная точка, её надежда и отчаяние, момент розыгрыша, например открытие, конец раунда или достигнутая отметка. | Кампания задаёт эффекты и упорядоченные условия перехода. Движок выбирает первый подходящий переход в фазе проверки сюжета. После розыгрыша конечной точки движок завершает партию. |

Выдача и списание ресурсов, начисление надежды и отчаяния, добавление события в указанную колоду, выдача и отмена квеста доступны в эффектах всех трёх контекстов. Для действия над личным инвентарём нужен определённый получатель. Если правило срабатывает при получении предмета, движок может передать персонажа, получившего его. При проверке после раунда автор может явно спросить, есть ли записка у кого-либо из персонажей. Это работает и в партии с несколькими персонажами.

Пример для ревью (имена команд условные). `(putOnTop .courier (currentTerritory))` допустимо во встрече. В сюжетной точке сборщик указывает на `(currentTerritory)` и объясняет, что у этой точки нет текущей территории. С явно указанной территорией `(putOnTop .courier (territory .square))` допустимо в обоих случаях. Общая команда принимает территорию из любого выражения подходящего типа. Настоящий квест «Забрать посылку» указывает площадь явно.

## Курьер: доступность, цена и последствия

У курьера `chooseOne` возвращает `Void`. У шерифа результат выбранной ветки имеет тип `Bool` и определяет, получит ли персонаж общую награду. [Сигнатуры ответов](../ScriptLanguage.md#выбор-игрока) · [Шериф в референсе](../../Reference/Domain/Cards/Tests/CardsTests/Resources/TestData/events/easttown1.police_station.yml)

```lisp
(chooseOne
  (caseIf "Обменять жетон на посылку"
    (hasItem .token)
    (do (removeItem .token) (addItem .parcel)))
  (case "Отказаться"
    (say "Тогда заберёте посылку на почте.")))
```

Условие `caseIf` только определяет доступность ответа. При показе встречи `(hasItem .token)` проверяет наличие жетона. Если жетона нет, игрок видит «Нужен 1 жетон» или авторский текст из `hint:`. После выбора обмена движок выполняет тело ответа по порядку. Команда `removeItem` списывает жетон, затем `addItem` выдаёт посылку. Оба эффекта входят в один атомарный розыгрыш встречи.

Для ответа «Предъявить жетон» автор использует ту же проверку `hasItem` и опускает `removeItem`. Жетон остаётся у персонажа.

Ранее тот же обмен рассматривали в построчной записи.

```yaml
id: courier
text: Курьер протягивает посылку и просит жетон.
script: |
  choose
    "Обменять жетон на посылку" when has(token, 1)
      take token 1
      give parcel 1
    "Отказаться"
      say "Тогда заберёте посылку на почте."
```

Пока игрок читает, жетон остаётся в инвентаре. Если его нет, обмен виден с пояснением «Нужен 1 жетон», а отказ игрок подтверждает сам. После отказа реплику можно перечитать в журнале.

На почте у встречи одна кнопка «Забрать посылку». У проводника подтверждение запускает три эффекта: списать посылку, выдать записку и добавить надежду. При получении посылки у курьера или на почте срабатывает условие квеста. Именно квест убирает невытянутую встречу и добавляет проводника на вокзал. Переход сюжета проверяет сама сюжетная точка после фазы встреч. [Сценарий и три маршрута](../Campaigns/LastTrain.md) · [Границы правил кампании](2026-11-13-define-campaign-rule-limits.md)

## Шериф: два пути к одной награде

Игрок либо убеждает шерифа проверкой влияния, либо тратит один трофей. При успехе любым путём получает значок и табельный пистолет. Провал влияния завершает встречу без награды. В [оригинале](../../Reference/Domain/Cards/Tests/CardsTests/Resources/TestData/events/easttown1.police_station.yml) обе ветки `chooseOne` возвращают логический результат: успех проверки или успешное списание трофея. Внешний `if` один раз описывает общую награду.

В **собственном построчном языке** можно поместить награду после выбора. При провале `end` завершает всю встречу. Трофей списывается только в ветке с доказательством.

```yaml
script: |
  choose
    "Убедить шерифа"
      if not test(influence)
        end
    "Показать доказательство" when has(remnant, 1)
      take remnant 1

  give deputy_sheriff
  give service_pistol
```

В **Yarn Spinner** строки после группы ответов также служат общим продолжением. `stop` завершает диалог. Проверку навыка, доступ к инвентарю и выдачу награды предоставляет DistrictDeck.

```yaml
script: |
  title: Sheriff
  ---
  -> Убедить шерифа
      <<if not test("influence")>>
          <<stop>>
      <<endif>>
  -> Показать доказательство <<if has("remnant", 1)>>
      <<take remnant 1>>

  <<give deputy_sheriff>>
  <<give service_pistol>>
  ===
```

В построчном варианте обсуждали общее продолжение и досрочный выход. В Lisp-подобном референсе результат выбора сразу служит условием внешнего `if`. Для шерифа оба способа позволяют записать награду один раз. Проверка навыка нужна здесь для сравнения языков. В «Последнем поезде» случайных проверок нет.

## Нейтан: несколько решений в одной встрече

Сначала персонаж делает покупки, затем решает, помочь ли Нейтану. При согласии игрок выбирает на карте клетку в пределах трёх шагов. Так одна встреча может обратиться к магазину, диалогу и карте. Если игрок вышел на вопросе о помощи, после загрузки он снова попадает в магазин с деньгами и инвентарём на начало встречи. Если игрок успел завершить встречу, покупки и итоговая позиция персонажа сохраняются вместе. [Исходная встреча](../../Reference/Domain/Cards/Tests/CardsTests/Resources/TestData/events/rivertown3.shop.yml)

Два рассмотренных способа прочитать тот же порядок действий:

```yaml
script:
  - shop:
      source: showcase
      rarity: common
  - ask:
      text: "Помочь Нейтану?"
      yes:
```

## Что проверить при выборе языка

- **Сборка.** Собрать каталог из базовых ресурсов движка и YAML кампании, затем проверить команды, аргументы и ссылки во всех ветках. Для команды выдачи различать опечатку в имени команды (`(adItem .parcel)`), неизвестный предмет (`(addItem .parcle)`) и событие на месте предмета (`(addItem .courier)`). Для одной и той же ошибки сборщик и приложение должны указать один и тот же путь, строку и столбец. Проверку проходимости выполняют отдельно эталонные маршруты.
- **Ответы.** У каждого достижимого вопроса есть доступный исход. Условие доступности можно вычислить до выбора без расхода ресурсов. При известной цене UI может объяснить недоступный ответ. Подтверждение на почте, отказ у курьера без жетона и два пути у шерифа проверяют разные случаи.
- **Исполнение.** Движок ведёт встречу до ожидания ответа или окончания. UI показывает запрос и передаёт выбор, тест без экрана делает тот же выбор. Проверить два перезапуска. Выход на втором вопросе возвращает к началу той же встречи. Выход сразу после её завершения сохраняет эффекты и продвигает очередь ровно один раз. Для первой кампании достаточно подтверждения и выбора ответа. Магазин и выбор клетки дают примеры для последующего расширения словаря.
