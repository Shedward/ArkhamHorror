# Спроектировать язык скриптов встреч

Подобрать короткую запись, по которой автор кампании может прочитать встречу от вопроса до последствий, а движок — разыграть её через UI и без экрана. Основной вариант для проработки — собственный построчный язык внутри YAML события. Сравниваем его с Yarn Spinner на одних и тех же встречах. Решение о языке и границах первой версии принимает автор проекта. Первый потребитель — [исходники «Последнего поезда»](last-train-first-play/2026-11-14-write-last-train-campaign.md).

**С чего продолжить.** У шерифа два пути к одной награде. Достаточно ли выполнять общие строки после выбора, а при провале досрочно завершать встречу командой `end`? Или удобнее, чтобы выбор возвращал результат, как в референсе? Обе записи разобраны ниже. Синтаксис ещё открыт.

Карточку можно закрыть, когда автор выбрал формат и по примерам понятны порядок команд, доступность ответов, ветвление, граница с игровым движком, ошибки при сборке и восстановление на ожидающем вопросе. Результат — описание с примерами, по которому можно написать три встречи «Последнего поезда».

## Решения

- Одно событие хранится в одном YAML. Его текст и подсказку для территории можно прочитать до розыгрыша. Динамическая часть описывает решения игрока и их последствия. Место и момент добавления события в колоду задаёт тот, кто его добавляет, например квест.
- В первой версии автор явно указывает `id` предметов и событий. Состояние партии может влиять на выбор ветки. При сборке проверяются команды и ссылки во **всех** ветках, включая тип сущности по каждому `id`. Приложение использует тот же валидатор при установке. [Архитектура](../Architecture.md)
- Встреча может несколько раз ждать решения игрока. При закрытии игры на втором вопросе сохраняются этот вопрос и последствия первого ответа. После восстановления первый ответ уже учтён ровно один раз. Следующий персонаж тянет событие после завершения всей встречи. [Правила розыгрыша и сохранения](../GameRules.md)

## Курьер: доступность, цена и последствия

```yaml
id: courier
text: Курьер протягивает посылку и просит жетон.
script: |
  choose
    "Обменять жетон на посылку" when has(token, 1)
      take token 1
      give parcel 1
    "Отказаться"
      say "Тогда заберёте посылку на почте."
```

Пока игрок читает, жетон остаётся в инвентаре. Если его нет, обмен виден с пояснением «Нужен 1 жетон», а отказ игрок подтверждает сам. После отказа реплику можно перечитать в журнале.

Обсуждали две записи цены. В примере `has` только проверяет предмет, а `take` списывает его после выбора. Запись вроде `cost: {token: 1}` позволила бы задать цену один раз для проверки, подсказки и списания. У отдельной проверки тоже есть применение: условие сюжетного перехода проверяет записку проводника и оставляет её у персонажа. Нужно решить, достаточно ли отдельных операций и когда окупается сокращение для цены.

На почте у встречи одна кнопка «Забрать посылку». У проводника подтверждение запускает три эффекта: списать посылку, выдать записку и добавить надежду. При получении посылки у курьера или на почте срабатывает условие квеста. Именно квест убирает невытянутую встречу и добавляет проводника на вокзал. Переход сюжета проверяет сама сюжетная точка после фазы встреч. [Сценарий и три маршрута](../Campaigns/LastTrain.md) · [Границы правил кампании](2026-11-13-define-campaign-rule-limits.md)

## Шериф: два пути к одной награде

Игрок либо убеждает шерифа проверкой влияния, либо тратит один трофей. При успехе любым путём получает значок и табельный пистолет. Провал влияния завершает встречу без награды. В [оригинале](../../Reference/Domain/Cards/Tests/CardsTests/Resources/TestData/events/easttown1.police_station.yml) обе ветки `chooseOne` возвращают логический результат: успех проверки или успешное списание трофея. Внешний `if` один раз описывает общую награду.

В **собственном построчном языке** можно поместить награду после выбора. При провале `end` завершает всю встречу. Трофей списывается только в ветке с доказательством.

```yaml
script: |
  choose
    "Убедить шерифа"
      if not test(influence)
        end
    "Показать доказательство" when has(remnant, 1)
      take remnant 1

  give deputy_sheriff
  give service_pistol
```

В **Yarn Spinner** строки после группы ответов также служат общим продолжением. `stop` завершает диалог. Проверку навыка, доступ к инвентарю и выдачу награды предоставляет DistrictDeck.

```yaml
script: |
  title: Sheriff
  ---
  -> Убедить шерифа
      <<if not test("influence")>>
          <<stop>>
      <<endif>>
  -> Показать доказательство <<if has("remnant", 1)>>
      <<take remnant 1>>

  <<give deputy_sheriff>>
  <<give service_pistol>>
  ===
```

Рабочее предложение — начать с общего продолжения и досрочного выхода. Преимущество возвращаемого значения в референсе — автор может использовать результат выбора в другом условии. Для шерифа оба способа позволяют записать награду один раз. Проверка навыка нужна здесь для сравнения языков. В «Последнем поезде» случайных проверок нет.

## Нейтан: несколько решений в одной встрече

Сначала персонаж делает покупки, затем решает, помочь ли Нейтану. При согласии игрок выбирает на карте клетку в пределах трёх шагов. Так одна встреча может обратиться к магазину, диалогу и карте. Если игрок закрыл приложение на вопросе о помощи, после загрузки покупки уже оплачены, вопрос открыт. [Исходная встреча](../../Reference/Domain/Cards/Tests/CardsTests/Resources/TestData/events/rivertown3.shop.yml)

Два рассмотренных способа прочитать тот же порядок действий:

```yaml
script:
  - shop:
      source: showcase
      rarity: common
  - ask:
      text: "Помочь Нейтану?"
      yes:
        - move: { upTo: 3 }
```

```yaml
script: |
  (do
    (shop (showcase) (limits (rarity common)))
    (if (ask "Помочь Нейтану?")
      (move 3)
      (doNothing)))
```

## Что проверить при выборе языка

- **Сборка.** Собрать каталог сущностей из YAML, затем проверить команды, аргументы и ссылки во всех ветках. Для команды выдачи различать опечатку в имени команды (`giev parcel 1`), неизвестный предмет (`give parcle 1`) и событие на месте предмета (`give courier 1`). В диагностике показать файл и строку. Проверку проходимости выполняют отдельно эталонные маршруты.
- **Ответы.** У каждого достижимого вопроса есть доступный исход. Условие доступности можно вычислить до выбора без расхода ресурсов. При известной цене UI может объяснить недоступный ответ. Подтверждение на почте, отказ у курьера без жетона и два пути у шерифа проверяют разные случаи.
- **Исполнение.** Движок ведёт встречу до ожидания ответа или окончания. UI показывает запрос и передаёт выбор, тест без экрана делает тот же выбор. Снимок партии хранит текущую встречу, персонажа и ожидающий шаг вместе с последствиями подтверждённых решений. Для первой кампании достаточно подтверждения и выбора ответа. Магазин и выбор клетки дают примеры для последующего расширения словаря.
