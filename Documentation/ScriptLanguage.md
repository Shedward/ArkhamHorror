# Язык скриптов DistrictDeck

Автор кампании описывает встречи, правила квестов и сюжетные точки на одном строго типизированном языке с Lisp-подобной записью. Словарь игровых операций поставляет движок. В архиве автор сочетает их в правила конкретного приключения. Новый вид операции добавляем, когда он нужен для конкретной механики. [Принципы проекта](Principles.md)

## Как записать скрипт

Одно событие хранится в одном YAML-файле. При осмотре территории интерфейс читает необязательные поля `hint.description` и `hint.highlight` из описания события до запуска скрипта. В поле `script` автор задаёт решения и последствия встречи. Когда и в какую колоду добавить это событие, указывает вызывающее правило, например правило выдачи квеста.

В скрипте одно корневое выражение. Форма начинается с имени, за ним идут аргументы. Форме без аргументов тоже нужны скобки. Вложенность задают скобки, поэтому аргументы можно переносить на новые строки. Для нескольких последовательных действий автор явно пишет `do`.

```ebnf
скрипт      = форма, конец_ввода ;
форма       = "(", имя, { значение }, { именованный }, ")" ;
именованный = метка, значение ;
метка       = имя, ":" ;
значение    = форма | целое | логическое | строка | ссылка | символ ;
логическое  = "true" | "false" ;
ссылка      = ".", id_кампании ;
имя         = буква_ASCII, { буква_ASCII | цифра } ;
символ      = имя - логическое ;
id_кампании = строчная_ASCII, { строчная_ASCII | цифра },
              { "-", (строчная_ASCII | цифра), { строчная_ASCII | цифра } } ;
строка      = '"', { знак_строки | экранирование }, '"' ;
экранирование = '\', ('"' | '\' | 'n') ;
```

| Запись | Что она означает |
| --- | --- |
| `(currentCharacter)` | Вложенная форма может получить значение из контекста. Тип результата определяет сигнатура. |
| `"Посылка у вас."` | Текст для игрока в двойных кавычках. |
| `1`, `-2` | Целое число. |
| `true`, `false` | Литералы типа `Bool`. Пишутся строчными буквами без кавычек и скобок. |
| `.parcel`, `.collect-parcel` | Явная ссылка на сущность кампании. После точки пишется ID из YAML, например `id: parcel`. Сигнатура определяет, в каком каталоге его искать. |
| `influence` | Символ, одно из известных движку значений ожидаемого типа. Пример из референса обозначает навык. |

Сначала идут позиционные аргументы в порядке сигнатуры, затем именованные в любом порядке. Метка пишется слитно с двоеточием и может встретиться в одном вызове один раз. Необязательный параметр пропускают целиком вместе с меткой. Знак пропуска `_` исключён из грамматики.

## Текст, имена и комментарии

В грамматике `знак_строки` — любой символ Unicode, кроме прямой двойной кавычки, обратной косой черты и перевода строки.

- **Команды, символы и метки.** Первая буква из `A–Z` или `a–z`, дальше допустимы те же буквы и цифры `0–9`. Регистр значим. Имена пишем в `lowerCamelCase`, например `chooseOne`, `influence`, `hint:`.
- **ID кампании.** После точки пишется точный ID из YAML. ID соответствует шаблону `[a-z][a-z0-9]*(-[a-z0-9]+)*`. Получаются короткие имена вроде `.gold`, `.post-office` и `.platform-2`. Такую же запись без точки автор использует в поле `id` и имени файла сущности.
- **Строки.** В двойных кавычках допустим текст Unicode, в том числе русские кавычки «ёлочки». Пустая строка `""` допустима. Поддерживаются три записи с обратной косой чертой: `\"` для прямой кавычки, `\\` для самой черты, `\n` для переноса строки в тексте игрока. Неизвестная последовательность даёт ошибку на обратной косой черте.
- **Переносы.** Между аргументами пробел, табуляция и перевод строки служат разделителями. Строковый литерал целиком пишется на одной строке исходника. При незакрытой кавычке сборщик указывает на начало литерала. Длинное статическое описание с абзацами удобно писать отдельным полем YAML `text: |`.
- **Комментарии.** В языке скриптов комментарии запрещены. Знак `;` вне строки — синтаксическая ошибка. Внутри кавычек он входит в текст реплики.

```yaml
script: |
  (do
    (addItem .parcel)
    (say "Поезд «Север» ждёт.\nПосадка у второго вагона."))
```

## Игровая лексика и имена команд

В каталоге группируем команды по тому, с чем работает автор. В скрипте пишем короткое имя в `lowerCamelCase` без префикса группы. Например, `addItem`, `removeItem`, `hasItem` и `itemCount` можно найти вместе в разделе «Инвентарь». Имена одинаковы во встречах, квестах и сюжетных точках. Контекст определяет, какие значения доступны при вызове.

| Область | Существительные | Глаголы |
| --- | --- | --- |
| Персонажи и поле | игрок `player`, персонаж `character`, карта `map`, клетка `cell`, территория `territory` | Игрок выбирает (`choose`), персонаж перемещается (`move`) и останавливается на клетке. |
| Объекты карты | объект карты `object` | Добавить на карту (`addObject`), убрать с карты (`removeObject`). |
| Инвентарь | инвентарь `inventory`, предмет `item`, ресурс `resource`, количество `count` | Добавить (`add`), убрать (`remove`), проверить наличие (`has`). В командах `Item` охватывает и предметы, и ресурсы. |
| Колоды и события | колода `deck`, событие `event`, сброс `discard pile` | Положить (`place`), замешать (`shuffle`), вытянуть (`draw`), отправить в сброс (`discard`). |
| Встречи и диалог | встреча `encounter`, выбор `choice`, ответ `answer` | Произнести реплику (`say`), задать вопрос (`ask`), выбрать (`choose`). Событие лежит в колоде, встреча начинается, когда персонаж его разыгрывает. |
| Квесты | квест `quest`, условие `condition` | Выдать (`start`), выполнить (`complete`), отменить (`cancel`). |
| Сюжет | сюжетная точка `storyPoint`, цель `objective`, отметка `milestone`, переход `transition` | Войти в точку (`enter`), достичь отметки (`reach`), перейти к следующей точке. |
| Партия и ходы | партия `game`, раунд `round`, фаза `phase`, ход персонажа `turn`, очко действия `actionPoint` | Потратить очко (`spend`), завершить ход (`end`). |

Глаголы в таблице описывают также работу движка. Например, движок сам вытягивает событие в фазе встреч и отправляет его в сброс. Команда нужна там, где решение принимает автор, например когда квест кладёт проводника в колоду вокзала.

- **Действие** называем глаголом с объектом. В `(addItem .parcel)` глагол описывает изменение инвентаря, а аргумент называет конкретный предмет. Вызов `(addItem .hope)` той же командой начисляет надежду партии.
- **Проверку** называем как вопрос. Например, `(hasItem .token)` читается как «есть ли жетон?». Метка `atLeast:` означает «не меньше», а `hint:` задаёт текст подсказки.
- **Значение** называем по результату. Например, `(itemCount .token)` возвращает количество, а `(currentCharacter)` возвращает персонажа из контекста встречи.
- **Управляющие формы** `do` и `if` задают последовательность и ветвление. Игровые сущности обозначаем ссылками вроде `.courier` или `.train-station`.

## Результаты выражений

`do` принимает хотя бы одно выражение и выполняет шаги слева направо. Все шаги перед последним должны иметь тип `Void`. Последнее выражение определяет тип и значение результата всего блока. Пустой `(do)` — ошибка сборки.

`if` принимает условие типа `Bool` и две ветки одного типа. При сборке проверяются обе ветки. При розыгрыше движок вычисляет условие один раз, выполняет выбранную ветку и возвращает её результат. Если обе ветки имеют тип `Void`, результат `if` тоже имеет тип `Void`.

Например, в этом фрагменте `say` имеет тип `Void`, а последний шаг `ask` возвращает ответ игрока типа `Bool`. Этот ответ становится условием для `if`.

```lisp
(if (do (say "Поезд готов к отправлению.") (ask "Посмотреть расписание?"))
  (say "Отправление в пять часов.")
  (say "Вы проходите на платформу."))
```

В аргументе типа `Bool` можно указать литерал или выражение с логическим результатом. Например, `(startQuest .collect-parcel repeatable: true)` передаёт логическое значение. Запись `"true"` даёт строку, а `.true` обозначает ссылку на сущность с ID `true`. Сборщик сообщит об ошибке типа, если передать одну из них в `repeatable:`.

## Условия, ответы и эффекты

Автоматические условия доступности ответа, выполнения квеста и перехода сюжета возвращают `Bool`. При одинаковом состоянии и контексте результат одинаков. Такие условия только читают состояние. Сборщик проверяет всё выражение, включая вложенные аргументы и обе ветки. Списание предмета, бросок кубика, запись в журнал или вопрос игроку внутри автоматической проверки дают ошибку сборки.

Формы `and`, `or` и `not` принимают значения типа `Bool` и возвращают `Bool`. При сборке проверяются количество и типы всех аргументов, а также ссылки на сущности внутри каждого условия.

`(hasCharacter .scout)` только читает состав текущей партии. Результат — `true`, если игрок выбрал скаута, и `false`, если скаут описан в кампании, но в эту партию не входит. Неизвестный ID персонажа даёт ошибку компиляции.

| Форма | Результат при розыгрыше |
| --- | --- |
| `and`, два условия или больше | Проверяет слева направо до первого `false`. Возвращает `true`, если все условия истинны. |
| `or`, два условия или больше | Проверяет слева направо до первого `true`. Возвращает `false`, если все условия ложны. |
| `not`, одно условие | Вычисляет условие один раз и меняет `true` на `false`, а `false` на `true`. |

Для перехода к развязке «Посылка отправлена» автор задаёт порог надежды в YAML через `at: { hope: 1 }`. В `when` скрипт проверяет наличие записки хотя бы у одного персонажа.

```lisp
(hasItem .conductor-note in: all)
```

Когда сюжет переходит в конечную точку, движок разыгрывает её и сам сохраняет как результат завершённой партии. В обычной точке, если ни одно условие перехода не сработало, игра продолжается со следующего раунда. [Правила развязки](GameRules.md#надежда-отчаяние-и-развязки)

Во встрече с шерифом обе ветки выбора возвращают `Bool`. Результат проверки навыка или траты трофея служит условием внешнего `if`, поэтому автор описывает общую награду один раз. [Встреча с шерифом в референсе](../Reference/Domain/Cards/Tests/CardsTests/Resources/TestData/events/easttown1.police_station.yml)

Для простого условия движок строит подсказку из его аргументов. Если `(hasItem .coin atLeast: 5)` возвращает ложь, интерфейс объясняет, что нужно пять монет. Автор может задать свой текст в том же вызове через `hint:`. Проверка сохраняет деньги в инвентаре. Списание автор явно указывает в теле выбранного ответа.

Каждый вызов `addItem` или `removeItem` меняет один инвентарь и возвращает `Void`. Для обеих команд `count:` задаёт количество, по умолчанию 1. Владелец общего ресурса известен по описанию вида. Например, `(addItem .hope)` добавляет партии одно очко надежды. Для личного предмета во встрече владельцем по умолчанию служит её участник. При передаче посылки проводнику `(removeItem .parcel)` списывает её у этого персонажа, а `(addItem .conductor-note)` выдаёт записку ему же. В контексте без текущего персонажа автор указывает владельца явно, например `(addItem .token in: .anna count: 2)`. [Доменная модель](DomainModel.md)

`count:` принимает целое число. Если автор указывает число прямо в скрипте, оно должно быть больше нуля: `count: 0` и отрицательный литерал дают ошибку компиляции. Если количество задаёт выражение, положительный результат — количество для выдачи или списания, а при нуле обе команды оставляют инвентарь без изменений и скрипт идёт дальше. Например, `(removeItem .token count: (itemCount .token))` списывает все жетоны текущего персонажа; если жетонов нет, вызов тоже завершается успешно. Отрицательный результат выражения — ошибка сценария: движок указывает позицию аргумента в исходном YAML и откатывает текущий скрипт.

`removeItem` списывает ровно запрошенное количество. Если в выбранном инвентаре меньше предметов, движок останавливает скрипт и откатывает все изменения этого запуска, включая эффекты предыдущих команд. Автор получает путь к YAML, строку вызова и причину ошибки, например `Cannot remove 2 tokens from .anna (available: 1)`. В обычном обмене у курьера условие `hasItem` заранее показывает игроку, доступен ли ответ.

`itemCount` возвращает точное целое количество, а `hasItem` сравнивает то же количество с включительным порогом `atLeast:`. По умолчанию порог равен 1. Если предмета нет, его количество равно нулю. Например, `(hasItem .despair atLeast: 5)` истинно и при пяти, и при шести очках отчаяния. Для частых ресурсов можно будет добавить сокращения над теми же операциями, например `(hopeCount)` для `(itemCount .hope)`.

Для личного предмета `hasItem` и `itemCount` принимают текущего персонажа (`in: current`), персонажа по ID (`in: .anna`) или сумму по личным инвентарям участников партии (`in: all`). Режим `in: all` доступен только для чтения. Если он указан в `addItem` или `removeItem`, сборщик сообщает об ошибке на строке вызова. Если у Анны два жетона, а у Бориса один, `(itemCount .token in: all)` вернёт 3, и `(hasItem .token in: all atLeast: 3)` даст истину. Для квеста «Забрать посылку» достаточно `(hasItem .parcel in: all)` — посылка может быть у любого участника.

## Выбор игрока

`say` передаёт реплику для показа и возвращает `Void`. Скрипт продолжает выполнение сразу. Закрытием реплики управляет интерфейс. При завершении встречи реплика входит в её запись журнала. [Показ реплик](GameRules.md#колоды-и-розыгрыш-встречи)

`chooseOne` принимает один или несколько ответов в порядке показа. Форма `(case "Текст" выражение)` задаёт всегда доступный ответ. В форме `(caseIf "Текст" условие выражение)` доступность определяет условие типа `Bool`, которое только читает состояние. Выражения всех веток должны возвращать один тип. Сборщик проверяет это и для условных ответов.

При розыгрыше `chooseOne` движок вычисляет доступность каждого ответа. Если доступен хотя бы один, движок передаёт интерфейсу или тесту все варианты с текстом, доступностью и пояснением для недоступного ответа. В ответ он получает номер выбранного доступного варианта из этого списка. Движок выполняет только выражение выбранной ветки. Его значение становится результатом `chooseOne`.

Если все ответы недоступны, движок сразу выдаёт ошибку сценария `No choices available` с путём от корня кампании, строкой и столбцом вызова `chooseOne` в исходном YAML. Весь розыгрыш встречи откатывается к его началу, включая эффекты предыдущих вопросов и записи журнала. Та же карта остаётся текущей встречей того же персонажа, и его место в очереди сохраняется.

У курьера обе ветки возвращают `Void`. Если у Ивана меньше пяти монет, он видит объяснение у платного ответа и может выбрать «Отказаться».

```yaml
id: courier
text: |-
  Курьер сидит на краю фонтана. При виде Ивана он поднимает свёрток.

  — За посылкой? С вас пять монет за доставку. А на почте заберёте бесплатно.
hint:
  description: Заплатить 5 монет
  highlight: mainQuest
script: |
  (chooseOne
    (caseIf "Заплатить 5 монет"
      (hasItem .coin atLeast: 5 hint: "Нужно 5 монет")
      (do (removeItem .coin count: 5) (addItem .parcel)))
    (case "Отказаться"
      (say "Тогда заберёте посылку на почте.")))
```

До ответа игрока розыгрыш приостановлен. Одна встреча может задать несколько вопросов подряд. Автор может описать все ответы через `caseIf`. При сборке и при установке проверяются команды, типы, ссылки и допустимость операций в условиях. Доказывать, что условия ответов охватывают все игровые состояния, не требуется.

При эталонном прохождении прогон сообщает ту же ошибку движка и дополнительно указывает встречу и шаг маршрута. Если доступны другие ответы, но недоступен именно записанный, прогон указывает расхождение на этом шаге. [Правила встреч](GameRules.md) · [Сценарий «Последнего поезда»](Campaigns/LastTrain.md)

## Выдача квеста

`(startQuest .collect-parcel)` выдаёт квест «Забрать посылку» только впервые за партию. Именно так его выдаёт начальная сюжетная точка «Последнего поезда». Параметр `repeatable:` имеет тип `Bool` и по умолчанию равен `false`. Команда возвращает `Void`.

Вызов `(startQuest .collect-parcel repeatable: true)` разрешает выдать этот квест и после выполнения или отмены. Разрешение действует только для данного вызова. Если квест уже активен, при любом значении `repeatable:` движок пропускает выдачу и все её эффекты. Если выдача состоялась, движок применяет её эффекты и сразу проверяет условие выполнения квеста.

## Отмена квеста

`(cancelQuest .collect-parcel)` отменяет активный квест «Забрать посылку» и убирает из колод оставшиеся копии событий, привязанные к этой выдаче. Если квест уже выполнен, отменён или ещё не выдавался, скрипт сразу переходит к следующему действию. Во всех случаях команда возвращает `Void`. Сборщик проверяет ID по каталогу квестов кампании.

## События в колоде территории

`placeEvent` кладёт новую копию события в колоду территории и возвращает `Void`. Первый аргумент — ID события, второй — ID территории. Именованный аргумент `position:` задаёт место новой карты. Порядок остальных карт сохраняется.

| Размещение | От верха колоды | От низа колоды |
| --- | --- | --- |
| На край | `top` — вытянут следующей | `last` — вытянут последней |
| В одно из N мест с равной вероятностью | `(amongFirst N)` — среди первых N | `(amongLast N)` — среди последних N |

N — положительное целое. Ноль и отрицательные значения в записи кампании дают ошибку сборки. Места считаются **после вставки**, включая новую карту. Если в колоде две карты, мест для вставки три: при `(amongLast 2)` доступны второе и третье, при `(amongLast 5)` — все три. В пустой колоде место одно. При N = 1 результат совпадает с `top` или `last` соответственно. Случайное место выбирает генератор партии.

При выдаче квеста «Забрать посылку» автор привязывает обе копии к этой выдаче через `forQuest: (currentQuest)`:

```lisp
(do
  (placeEvent .courier .square position: top forQuest: (currentQuest))
  (placeEvent .post-office .post-office position: top forQuest: (currentQuest)))
```

После всех эффектов встречи движок сразу проверяет условие той выдачи квеста, на которую указывает `forQuest:` у вытянутой копии, если эта выдача ещё активна. При истинном условии движок завершает квест и разыгрывает его эффекты до следующей встречи.

При выполнении или отмене квеста движок убирает его неразыгранные копии из колод. Разыгранная встреча уходит в сброс. Без `forQuest:` копия независима, даже если её добавил скрипт квеста. Так, при выполнении «Забрать посылку» вызов `(placeEvent .conductor .station position: top)` оставляет проводника на вокзале для следующей встречи.

## Старт партии

Скрипт кампании `onStart` работает с выбранным составом после размещения всех персонажей на клетке `initialPoint` и до открытия `initialStoryPoint`. Он выполняется один раз при создании партии. В этом контексте у партии нет текущего персонажа, поэтому автор указывает получателя личного предмета по ID.

```lisp
(do
  (moveTo .ivan .station-start)
  (addItem .coin in: .ivan count: 5))
```

`moveTo` принимает ID персонажа и ID клетки назначения. Такое перемещение по эффекту скрипта сохраняет очки действий и доступное число перемещений за ход.

Если `addItem` выдаёт личный предмет или `moveTo` перемещает персонажа, которого нет в партии, движок сообщает об ошибке сценария с позицией вызова в YAML и откатывает весь текущий скрипт. Это правило действует и после старта партии. Например, если Иван обязателен, а скаут доступен для выбора, стартовый жетон можно выдать скауту при его участии, а в остальных партиях — Ивану.

```lisp
(if (hasCharacter .scout)
  (addItem .token in: .scout)
  (addItem .token in: .ivan))
```

## Объекты карты

`(addObject .train)` добавляет на карту поезд, а `(removeObject .train)` убирает его. Обе команды возвращают `Void` и доступны в скриптах эффектов. Компилятор разрешает аргумент по ID в разделе `objects` файла `board/scene.yaml`. При неизвестном ID он указывает позицию ссылки в YAML скрипта.

Один ID обозначает один объект карты. Если объект уже на карте, повторный `addObject` ничего не меняет. Если объект объявлен в кампании, но сейчас отсутствует на карте, `removeObject` тоже ничего не меняет. В обоих случаях скрипт продолжает выполнение.

Движок учитывает присутствие объектов и при игре без экрана. Изменение входит в тот же атомарный розыгрыш, что и остальные эффекты скрипта. После загрузки партии сцена показывает объекты, присутствующие в сохранённом состоянии карты.

## Компиляция и контекст

`CampaignTool` при сборке и приложение при установке используют один компилятор ядра. Перед разбором скриптов загрузчик собирает каталог по типам сущностей из базовых ресурсов движка и описаний в архиве. В пределах одного вида сущности ID должен быть уникален во всём каталоге. Если архив объявляет предмет или ресурс с системным ID, сборщик и загрузчик сообщают об ошибке и указывают файл объявления. Скрипты могут свободно ссылаться на встроенные ресурсы. Например, начисление `.hope` меняет количество надежды в общем инвентаре. При разборе каждой формы компилятор сразу строит типизированную Swift-структуру. Он проверяет имя команды, аргументы, тип результата, ссылки на сущности и доступность операции во всех ветках.

Например, в `(addItem .parcel)` сборщик ищет `parcel` среди предметов. В `(addItem "parcel")` ошибка относится к строке на месте ссылки. Аналогично можно указать на опечатку в метке `hnt:`, повторную метку или число вместо строки в `hint: 42`. Проходимость кампании проверяется отдельно по эталонным маршрутам. [Архитектура](Architecture.md)

У движка один каталог команд. Команда объявляет, какие данные ей нужны, а место запуска определяет, какие данные получит скрипт. Из каталога компилятор выбирает доступный набор для этого контекста. Во встрече известны вытянутое событие, персонаж и территория. Правило квеста знает текущий квест, правило сюжетной точки — текущую точку. Например, во встрече доступно выражение `(currentTerritory)`. Сюжетная точка, которая добавляет событие на площадь, может указать территорию явно. Обращение к текущей территории в месте, где движок её не передаёт, обнаруживается при сборке.

## Сохранение розыгрыша

Каждый запуск скрипта атомарен для сохранения партии. Пока встреча открыта, следующий шаг видит эффекты предыдущих ответов. Если игрок закрыл приложение на втором вопросе, при загрузке тот же персонаж разыгрывает ту же встречу с начала. Восстанавливаются входное состояние партии, очередь и состояние генератора случайности, если он использовался.

Когда встреча завершена, движок одним сохранением фиксирует её эффекты, результат проверки связанного квеста и его последствия, журнал, сброс карты и продвижение очереди. Ошибка в эффектах квеста откатывает весь розыгрыш встречи. [Сохранение партии](GameRules.md)

## Диагностика ошибок скрипта

`CampaignTool` и приложение показывают ошибку в формате `путь:строка:столбец — причина`. Текст причины пишем на английском. Путь задаётся от корня кампании. Строка и столбец отсчитываются с единицы в исходном YAML-файле с учётом его отступов и переносов.

Для неизвестного ID позиция указывает на точку перед именем, для неизвестной команды — на первую букву её имени, для незакрытой строки — на открывающую кавычку. Например, в файле `events/collect-parcel/courier.yaml` допущена опечатка в ID предмета.

```yaml
id: courier
script: |
  (addItem .parcle)
```

```text
events/collect-parcel/courier.yaml:3:12 — Unknown item ID .parcle
```
