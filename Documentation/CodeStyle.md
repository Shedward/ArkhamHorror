# Стиль Swift-кода DistrictDeck

**Файлы.** Основной тип даёт имя файлу. Второй тип верхнего уровня уместен, когда оба образуют пару. Максимум — два типа на файл. Типы, которые используются только внутри основной сущности, вкладываем в неё через `extension` в конце файла. Подпапки называем по назначению кода. Например, базовые выражения языка лежат в `Scripting/Expressions/Builtins`, каждое в своём файле.

**Объявления.** Группу свойств отделяем от методов пустой строкой. Между членами типа (`static`, `class`) и членами экземпляра тоже оставляем пустую строку. Тела вычисляемых свойств, геттеров, сеттеров, методов и инициализаторов пишем на отдельных строках, даже когда тело состоит из одного выражения. Требование протокола может оставаться кратким, например `static var name: String { get }`.

**Комментарии.** Сначала стараемся выразить смысл именами, структурой кода, диагностикой или проверкой инварианта. Комментарий оставляем, когда нужно:

- Объяснить обстоятельства, из-за которых понадобилось обходное решение.
- Кратко описать идею или алгоритм, который трудно прозрачно выразить кодом.
- Сохранить контекст принятого решения или предупредить о последствиях внешне безобидной правки.

Если причина выходит за эти три случая, сначала обсуждаем её с автором.

**Проверка.** Из корня проекта запусти `Tools/lint --strict`. Та же проверка при сборке показывает замечания в Xcode. SwiftLint проверяет базовые правила, а проверки структуры объявлений используют SwiftSyntax из установленного Xcode.
